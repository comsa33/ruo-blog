I was building long-term memory for an agent. Facts a user drops during a conversation get extracted, stored, and recalled in later sessions.

One day I opened the store and read this:

> User asked why pgvector 0.8 is necessary for service deployment.

The conversation had been in Korean from beginning to end.

## Where this happens

Structure first. The memory service doesn't own the transcript. The transcript lives in exactly one place, and this service holds only summaries, cursors, and memories.

Not replicating the transcript was the best early decision we made. Retention, deletion requests, and the boundary of personal data all stay the problem of one store. The cost is that the worker has to re-read the original every time.

## Why per-turn extraction doesn't work

The first design was simple: a turn arrives, extract that turn.

We were resending 98% of the input every time to process 2%, so I decided to batch turns and share the fixed cost across them.

Batches of five cut it by 4.6×. Push the slider further and it does keep dropping, but almost all of the saving from sharing the fixed cost comes in the first few steps, and after that you're only adding delay before a memory gets stored. In the real service memory is needed at the session level anyway, and five turns or so sat closest to that.

## No placement of the instruction worked

If fixed cost is 80%, batching isn't the only option; you can also shrink the fixed cost itself. That's why I opened the prompt, and that's how I ran into the language problem.

At first I just told it to: write in the same language as the input. I tried four conditions.

| Condition | Instruction placement                      | Result  |
| --------- | ------------------------------------------ | ------- |
| A         | 8 lines at the end of the user prompt      | English |
| B         | End of the system prompt, forcefully       | English |
| C         | Start of the system prompt, forcefully     | English |
| E         | Minimal prompt with no examples + one line | Korean  |

A, B and C came out in English wherever the instruction went, and the only one that came out in Korean was E, the one with every example removed.

## The cause was fourteen examples

The prompt was 33,661 characters and contained fourteen English few-shot examples. The word `language` appeared zero times in all of it, and there wasn't a single Korean character. Nobody knew that until I read the prompt from the top to shrink it.

My guess is that fourteen demonstrations of "take Korean, write English" simply weighed more than one line of instruction.

<Callout label="A related discovery" accent>
  The previous version of the open-source memory engine we were using had `record the facts in the
  same language` written into the prompt body. The next version moved it behind an option, so it
  silently left the default behaviour. It was not in the upgrade notes.
</Callout>

## What came along with it

Rewriting the examples was also a chance to encode two contaminations that had been sitting there.

The first is recall re-ingestion. A user asks "what did I say I liked?", the agent lists stored memories back, and that listing gets extracted as new facts. Copies of the same fact multiply every time the topic comes up.

The second is absence statements. "There is no record of that" was being stored as a memory that there is no record.

| Contamination        | Before        | After         |
| -------------------- | ------------- | ------------- |
| Recall re-ingestion  | 2/7           | 0/7           |
| Absence statements   | 5/7           | 0/7           |
| Attribution accuracy | no regression | no regression |

How fast copies actually accumulate only shows up across sessions. Fifteen consecutive sessions, counting cumulative duplicates:

Without suppression, copies grow linearly. The final version stops growing at 3 from the seventh session on, which means restating the same fact no longer produced a new copy. Through all of it, 22 of 24 legitimate facts were kept.

## What I couldn't fix

It also became clear what a prompt can't do.

The agent suggests "navy is a safe choice", the user says nothing at all, and "the user prefers navy" gets stored. Instructions didn't stop it. Extra examples didn't. A dedicated non-response example didn't. Three attempts, three failures.

Fabricating decisions that were never made is fully blocked by rules now. But deciding whose opinion something that was said belongs to didn't work in the prompt, and I think it has to be handled in a filtering layer after ingestion.
